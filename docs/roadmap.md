# 设计交付与实现顺序

当前只整理设计。实现前完成架构文档和关键技术验证，再拆分任务。

1. 明确与 AXP 的服务契约、领域模型、数据归属和状态转换。
2. 验证 oar 驱动容器内 Claude/Codex：输出、追问、中断、插件、审批与重启恢复，形成能力矩阵。
3. 环境草稿、不可变版本、插件组装和构建计划。
4. 构建 worker、状态恢复、日志、缓存、镜像发布及凭据处理。
5. 实例协调、工作区持久化、会话恢复、重启与版本切换。
6. AXP 集成、环境编辑、构建观察及 Agent 自助管理工具。
7. 现有 Agent 迁移、运维诊断与资源清理。

## 验收场景

- 选择 runtime 和插件，构建并启动，完成一次真实任务。
- 修改环境并重建，构建失败时当前实例仍可用。
- 重启后仓库保留，原生会话按实际支持能力恢复。
- 重复请求、网络超时和控制器重启不产生重复实例。
- 构建 worker 中断后可核对状态，取消和重试结果明确。
- 启动脚本失败和版本切换失败可诊断并恢复。
- 节点失联时避免两个实例同时写工作区。
- 不兼容插件在启动前被拒绝。
- Agent 请求重建自身环境后，可继续查询异步操作结果。
- 构建/运行/会话可通过关联 ID 在日志与 OTel 中定位；密钥不进入产物与日志。

# 架构设计草案

## 服务边界

`sandboxed-agent-builder` 是独立服务，负责环境版本、构建、镜像产物和运行实例。AXP 负责 Agent 身份、任务编排、对话产品与用户配置的连接；通过外部 Agent ID 关联本服务资源。

服务内部区分环境、构建和运行三个领域。领域与应用层不依赖 Docker、BuildKit 或 oar 的具体类型；基础设施 adapter 实现对应接口。容器内 bridge 是单独部署的执行组件，不能访问构建控制平面或宿主 Docker socket。

## 领域对象

| 对象 | 职责 |
| --- | --- |
| Environment | 可编辑环境的归属和草稿 |
| EnvironmentRevision | 不可变环境规格，含基础镜像、runtime/oar、插件、脚本、目标平台和凭据引用 |
| Build | 对一个版本和平台的一次构建尝试、状态、日志与失败原因 |
| ImageArtifact | 可部署的镜像 digest、平台、来源构建与版本 |
| RuntimeInstance | 外部 Agent 的实际运行实例、镜像、节点、工作区与运行代次 |
| Operation | 异步生命周期请求及其持久化结果 |
| Workspace | 独立于镜像和实例的工作区数据 |
| Session | 原生 runtime 会话 ID、恢复元数据和事件记录 |

修改草稿不影响运行实例。发布版本后不可变；重复构建可产生不同尝试，实际产物由 digest 标识。模型及指令变更是否需要重新构建，应由配置分类决定，不能全部强制重建。

## 模块

- 环境管理：草稿、发布、插件锁定、兼容性检查和确定的构建计划。
- 构建管理：任务调度、取消、重试、日志、缓存和产物发布，通过 BuildKit adapter 执行。
- 产物管理：确认镜像可用，跟踪引用，定义保留和清理策略。
- 运行控制器：协调期望与实际状态，通过容器 adapter 启动、停止和替换实例。
- 插件适配：生成 runtime 原生 skills、MCP、plugins、hooks 等配置。
- runtime bridge：通过 oar 处理消息、输出、中断、追问和恢复，并报告实际就绪状态。
- 凭据接口：运行时解析引用；构建私有依赖时使用临时 build secret。

构建 worker 与运行执行器需要明确授权和失败边界。初始部署拓扑待评审，但独立服务边界及内部职责从设计开始确立。

## 镜像组装

基础系统与 bridge/oar → runtime → 按稳定顺序排列的插件安装步骤 → 用户构建脚本。

每个插件组织独立 layer，利用 BuildKit 缓存。早期 layer 改动会使后续缓存失效。相同版本和平台可以共享产物。

锁定基础镜像 digest、runtime/oar 版本及插件内容。脚本下载依赖也需锁定才能承诺可复现。缓存标识覆盖构建输入；缓存命中不代替产物来源记录。

构建脚本负责镜像内依赖；启动脚本在挂载工作区并注入运行凭据后执行。启动脚本需定义重复执行、超时和失败语义。密钥不得进入镜像 layer、环境版本正文或日志。

## 生命周期

构建状态初稿：queued → running → succeeded / failed / cancelled。

实例阶段初稿：pending → starting → ready → stopping → stopped；失败记录具体阶段和原因。会话恢复和任务继续执行分别报告，不能由 ready 推断。

保存配置、发布版本、构建产物和应用版本是独立操作。构建失败不影响当前实例。应用版本时等待当前轮次结束或明确中断，确认旧实例停止写入后才能启动新实例写同一工作区。

每个工作区只能有一个有效写入实例。运行代次及租约/隔离机制需覆盖控制器重启、重复请求和节点失联，不能仅依赖进程内锁。幂等键绑定请求内容；超时后先核对结果，再决定是否重试。

重启保留工作区与会话数据。镜像回退不会撤销文件改动；原生会话数据被新版迁移后，旧 runtime 是否能恢复需要单独验证。跨 runtime 不承诺原生会话迁移。

Agent 请求修改或重建自身环境时，先返回 operation/build ID，再由外部控制器处理。正在被替换的实例不负责证明自己的替换已完成。

## oar 与插件

oar 提供 runtime 会话抽象，不是通用插件安装器。Claude/Codex 的插件主要依赖原生配置；技能、MCP、hooks、审批和恢复能力必须逐组合验证。

提供明确的 runtime/插件兼容矩阵。无法满足的能力明确拒绝，不能静默丢弃；插件定义不重复复制进 prompt。现有 AXP plugins-go 和 akhook 需评估复用与适配，不能假定 oar 会自动保留其语义。

## 外部契约待设计

- 环境草稿、版本发布、兼容性查询。
- 构建提交、取消、状态、日志与产物查询。
- 实例创建、停止、重启、版本应用及 operation 查询。
- 会话输入、中断、事件订阅及断线补查。
- 凭据引用和执行节点授权。

正式 API 需明确分页、事件序号、幂等、错误码、认证及版本策略。持久化状态是事实来源，事件订阅用于通知；消费者断线后应可补查。
